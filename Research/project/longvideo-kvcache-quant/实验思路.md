# LongVideo KVCache Quant 实验思路

## 核心假设
先把问题压缩成三个最值得验证的假设：

1. 通用 LLM KV 量化方法可以迁移到 forcing-based 长视频生成，但退化模式会更偏向 motion 而不是静态画质。
2. 长视频生成中的历史缓存不是同质的，不同时间角色需要不同量化精度。
3. “先结构化选择，再量化”会比“直接全缓存统一量化”更稳。

另外可以单独拉出一个更直接、也更符合老师建议的工作假设：

4. 不同 attention head 对长视频生成的重要性不同，因此在相同平均 bit 预算下，`important heads with high-bit + unimportant heads with low-bit` 会优于 uniform quantization。

## 实验总路线
建议按三阶段推进，不要一开始就直接做最终方案。

### 阶段 1：建立视频生成量化基线
目标：回答“量化这件事在 forcing-based 长视频生成里到底可不可行”。

建议基线：
- 母体模型：`Self Forcing`
- 强对照：`Rolling Forcing`
- 视频量化对照：`Quant VideoGen`

优先实验：
- FP16 / BF16 全精度 baseline
- 统一 8-bit KV
- 统一 4-bit KV
- 统一 2-bit KV

关注点：
- 视频能否稳定 roll 到 30s / 60s
- 退化首先出现在画质、身份一致性，还是 motion dynamics

### 阶段 2：迁移通用 LLM KV 量化方法
目标：回答“哪些通用量化方法能迁过来，哪些会在视频里失效”。

建议优先迁移：
- `KIVI`
- `KVQuant`
- `GEAR`

最小对照表：
- uniform per-tensor quant
- KIVI-style asymmetric quant
- KVQuant-style long-context quant
- GEAR-style near-lossless compression

这一阶段的重点不是赢指标，而是摸清误差形态：
- key 比 value 更敏感，还是相反？
- prefill 阶段量化敏感，还是 rollout 中增量写 cache 更敏感？
- 量化误差会不会沿 diffusion steps 被放大？

### 阶段 2.5：先评估老师的 head-wise mixed-precision 思路
目标：先不急着做完整方法，而是验证“按 head 重要性分配 bit”这件事本身值不值得继续做。

核心设定：
- 重要 head 用高 bit
- 不重要 head 用低 bit
- 先固定总平均 bit 预算，再和 uniform quantization 做公平对照

建议先把它当成一个 evaluation protocol，而不是最终算法。这样可以先回答：
- head importance 是否真的存在稳定排序？
- 同样平均 bit 下，mixed precision 是否优于 uniform 4-bit / uniform 3-bit？
- 收益主要体现在 identity、scene consistency，还是 motion dynamics？

### 老师思路的最小验证方案
先只做最容易落地的一版，不要一开始就搞复杂 online policy。

#### Step 1：先定义 head importance
先选一个最便宜、最容易复现的 proxy，然后只用这一种 proxy 起步。

我建议优先顺序是：
- attention mass / attention score concentration
- ablation sensitivity：逐个或逐组把某些 head 降精度，看质量下降幅度
- activation magnitude：看对应 head 的 `K/V` 范数或输出范数

其中最适合作为第一版的，是 `ablation sensitivity`：
- 先从 full precision 或 uniform 4-bit 出发
- 每次只把一组 heads 降到更低 bit
- 看视频指标下降多少
- 下降越大，说明这一组 heads 越重要

这样得到的不是“解释型重要性”，而是“对量化最敏感的重要性”，更贴合当前课题。

#### Step 2：先做分组，不急着精确到单个 head
不要一开始就做 per-head 精细搜索，成本太高。

建议先按每层或全模型把 heads 分成三组：
- top important heads
- middle heads
- least important heads

然后做类似下面的 bit 分配：
- top group: `4-bit`
- middle group: `3-bit`
- bottom group: `2-bit`

或者更保守一点：
- top group: `8-bit`
- bottom group: `2-bit`

前提是把平均 bit 控在和 uniform baseline 接近，例如：
$$
\bar{b}=\frac{1}{H}\sum_{h=1}^{H} b_h
$$
并让 mixed-precision 配置与 `uniform 4-bit` 或 `uniform 3-bit` 在平均预算上可比。

#### Step 3：先做静态 importance，再看是否值得做动态 importance
第一轮实验里，importance ranking 最好固定：
- 要么离线在验证集上统计一次
- 要么在短 rollout 上统计一次后全程复用

不要一开始就做 frame-wise 或 step-wise 动态重分配，否则系统复杂度会淹没结论。

只有当静态排序已经明显优于 uniform baseline，再考虑：
- per-layer ranking
- per-sample ranking
- per-stage ranking（prefill 和 rollout 用不同排序）

## 先评估老师思路的实验矩阵
这个矩阵的目标不是发论文，而是尽快判断这条路值不值得深挖。

### 对照组
1. full precision
2. uniform 4-bit
3. uniform 3-bit
4. uniform 2-bit

### 老师思路组
1. head-wise mixed precision，平均 bit 对齐 `uniform 4-bit`
2. head-wise mixed precision，平均 bit 对齐 `uniform 3-bit`

### 可选附加组
1. 只对 `K` 做 head-wise mixed precision
2. 只对 `V` 做 head-wise mixed precision
3. `K/V` 使用同一 importance 排序
4. `K` 和 `V` 分别排序

## 先看什么结果
如果老师这条思路成立，应该优先看到下面几类现象：
- 在相同平均 bit 下，mixed precision 比 uniform quantization 质量更高
- mixed precision 的收益不是随机波动，而是在多个 prompt / 多段视频上稳定存在
- 高重要性 heads 被保护后，长时 identity consistency 或 motion continuity 明显更稳

最重要的不是绝对数值领先多少，而是先看趋势是否稳定。

## 成功标准
我建议把“是否继续做这条线”设成一个明确 gate：

- 如果在相同平均 bit 下，head-wise mixed precision 相对 uniform baseline 有稳定收益，这条线继续推进
- 如果收益很弱，或者排序对不同样本非常不稳定，就不要把它当主线，只保留为消融
- 如果 head-wise 收益有，但明显弱于 role-aware 收益，那么它更适合作为 role-aware 方法中的局部模块，而不是最终核心卖点

## 为什么这个方案适合现在先做
- 它直接回应老师的想法，沟通成本低
- 它比完整的 role-aware 方法更轻，适合先做 feasibility check
- 它能顺手回答“到底是不是某些 heads 更怕量化”这个关键问题
- 即使最后不做成主方法，这组实验也能沉淀成后续论文里的重要动机或消融

### 阶段 3：做视频特化 / 角色感知量化
目标：做出真正属于这个项目的方案。

我建议优先尝试两个方向：

方向 A：时间角色感知量化
- `sink` 用高精度
- `tail` 用中等精度
- `history` 用低精度

方向 B：结构化选择 + 量化联合
- 先用 `Relax Forcing` 或 `Deep Forcing` 的记忆结构做选择
- 再只对被选中的不同角色分配不同 bit-width

这一步最有可能产出一个明确的方案原型，比如：
$$
\mathcal{M}_{i}=\mathcal{S}\cup\mathcal{H}_{i}\cup\mathcal{T}_{i}
$$
并令：
$$
Q(\mathcal{M}_{i})
=
Q_{b_s}(\mathcal{S})
\cup
Q_{b_h}(\mathcal{H}_{i})
\cup
Q_{b_t}(\mathcal{T}_{i})
$$
其中通常希望满足：
$$
b_s > b_t > b_h
$$

## 评测指标
这个项目不能只看一般推理精度，必须把“长视频真的能不能活到后面”测出来。

### 质量指标
- `Dynamic Degree`
- `Motion Smoothness`
- `Overall / Subject / Background Consistency`
- `Imaging Quality`
- 如果方便，补充人工偏好或 LLM-as-a-judge 的长时稳定性判断

### 系统指标
- KV cache 峰值显存
- 端到端生成时延
- tokens / frames per second
- 单卡最大可生成时长

### 关键曲线
- bit-width vs 质量曲线
- bit-width vs 时长上限曲线
- 压缩率 vs dynamic degree 曲线

## 关键消融
这部分决定最后有没有论文味道。

### 1. 量化粒度
- per-tensor
- per-channel
- per-head
- per-token / per-frame

### 2. 量化对象
- 只量化 `K`
- 只量化 `V`
- 同时量化 `K/V`

### 3. 时间角色
- full dense memory 统一量化
- `sink/history/tail` 分角色量化
- `deep sink + selected history + recent tail` 分角色量化

### 4. 写入时机
- prefill 后一次性压缩
- rollout 中增量写入时即时量化
- 滑窗满后再重压缩

## 最小可行实验
如果想先快速起盘，我建议只做下面这 6 组：

1. `Self Forcing` full precision
2. `Self Forcing` uniform 4-bit KV
3. `Self Forcing` uniform 2-bit KV
4. `Self Forcing + KIVI`
5. `Self Forcing + Quant VideoGen`
6. `Relax Forcing + role-aware mixed precision`

只要这 6 组跑通，你就能很快看出：
- 通用量化是否可迁移；
- 视频专用量化是否确实更稳；
- 结构化记忆是否值得和量化联合。

如果当前想先专门评估老师的想法，可以再压缩成一个更小的 5 组版本：

1. `Self Forcing` full precision
2. `Self Forcing` uniform 4-bit KV
3. `Self Forcing` uniform 3-bit KV
4. `Self Forcing` head-wise mixed precision（平均 bit 对齐 4-bit）
5. `Self Forcing` head-wise mixed precision（平均 bit 对齐 3-bit）

这 5 组更适合拿来快速回答：
- “按 head 重要性分 bit”到底有没有用；
- 它的收益是否值得继续投入更复杂的方法设计。

## 我最看好的论文切口
如果目标是最后做成一篇自己的工作，我更看好下面这个切口：

### 角色感知 KV 量化
核心论点：
- 长视频 forcing 里的缓存不是同质 memory；
- 不同时间角色承担不同语义功能；
- 因此 bit allocation 不该只按 layer/head 分，而该按 memory role 分。

一句话版本可以概括成：
> 不是所有历史都值得同样精度地记住。

## 当前执行顺序建议
- 先读：[[Relax-Forcing]]、[[Deep-Forcing✅]]、[Quant VideoGen](https://arxiv.org/abs/2602.02958)
- 再跑：uniform 4/3/2-bit baseline
- 然后先做：teacher idea evaluation，即 `head-wise mixed-precision under fixed average bit budget`
- 再复现：`KIVI`、`KVQuant`
- 最后再决定主线是 `head-wise mixed precision` 还是 `role-aware mixed-precision KV cache for long video forcing`

## 风险点
- 视频生成评测开销高，单次 ablation 成本比 LLM 大很多；
- 很多通用 KV 量化方法默认 decoder-only LLM，不一定能直接落到 video diffusion attention 实现；
- 即使静态帧质量没掉，长时 motion 也可能先坏；
- 如果没有一个稳定可复现的 forcing 基线，量化实验会很难解释。

## 现阶段的最重要结论
当前阶段最值得先验证的，不是“2-bit 能不能跑”，而是：
- 长视频里到底是谁最怕被量化；
- 是 `K` 怕，还是 `V` 怕；
- 是 `sink` 怕，还是 `history` 怕；
- 是不是某些 `heads` 天然更值得高 bit 保护；
- 是画质先坏，还是动态先坏。

把这四个问题测清楚，后面的方案设计就会非常顺。

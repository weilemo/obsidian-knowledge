# Paper Folder Agent Rules

适用范围：`/Users/moweile/Obsidian/Knowledge/Research/Paper` 及其所有子目录。

## 0. 总原则
- 新增/重写论文笔记时，不要求机械复刻原论文目录结构；允许按“研究卡”方式重组，但必须忠实覆盖原论文的核心内容与逻辑。
- 若原文结构本身对理解方法非常关键（如 Problem Setup、Preliminaries、Ablation、Limitations），应在笔记中保留这些信息，而不是为了统一模板删掉关键层次。
- 优先复用已有目录与地图笔记，避免重复文件与重复分类。
- 任何新论文加入时，默认同时考虑“可管理性”与“可检索性”（目录、标签、状态、发表日期、双链）。
- 每次新增论文时，都要顺手检查当前文件夹内是否存在更好的分类方式；若发现现有分类开始拥挤、混杂或边界不清，需要给出可执行的调整建议。

## 1. 论文卡片必填元数据
每篇 `type: paper` 笔记必须包含：
- `created`
- `published`（论文发布日期，格式 `YYYY-MM-DD`）
- `type: paper`
- `status`（仅允许：`已读` 或 `未读`）
- `tags`
- `aliases`
- `summary`
- `pdf-url`
- `source-url`

若缺少 `published`，必须先补齐再完成交付。

## 2. 内容质量要求
- 正文必须围绕论文真实贡献展开，不得只写口号式摘要。
- 重写论文卡默认采用“细讲版”标准，而不是概述版。
- 重点写清：问题定义、核心方法、关键公式/机制、实验设置、主结论、局限。
- 讲方法时优先写透实现机制、变量含义、误差来源、设计动机与关键公式，做到可用于复现思路和横向比较。
- 不要求每篇都按同一标题模板写，但内容密度必须足够，不能只停留在“这篇论文做了什么”的层面。
- 如果论文中存在核心公式、关键目标函数、量化/压缩表达式、复杂度公式或误差分解，默认应写入笔记；除非该公式对理解贡献确实不重要。
- 避免重复铺垫和反复解释已经讲过的背景。写作上优先“先结论，再机制，再公式”，减少空泛过渡句和同义反复。
- “启发”“评注”“相关工作对比”只保留高价值内容，不为凑完整度重复正文观点。
- 含数学内容时必须使用 LaTeX 语法（块级优先 `$$...$$`，行内 `$...$`）。
- 默认在文末增加“相关链接（双向）”，至少链接到所属主题总览（如 `[[KV Cache]]`、`[[Sparse Attention]]` 等）。

## 3. 文件命名与分类规则
- 文件名默认使用英文论文标题的短横线风格（如 `Longformer-The-Long-Document-Transformer.md`）。
- 若下载论文 PDF 到本地，必须放入当前主题目录下的 `Attachments/` 子目录，禁止把 `.pdf` 裸露放在主题目录根下。
- 本地 PDF 的 `pdf-url` 优先写成相对路径 `Attachments/<filename>.pdf`；只有未下载本地文件时，才直接写远程 PDF 链接。
- 目录分类优先按“方法本质”而非任务表象：
  - `KV_cache/00_架构先验`：MHA/MQA/GQA 等架构层改造
  - `KV_cache/10_Budget分配`：跨层/跨头预算分配
  - `KV_cache/20_重要性判断`：token/head 重要性打分与淘汰
  - `KV_cache/30_流式缓存与无限上下文`：sink/recent/rolling 等流式缓存
  - `KV_cache/40_分层存储与外存管理`：GPU-CPU-Disk/offload/retrieval
  - `KV_cache/50_量化与编码压缩`：KV quantization/PQ 等编码压缩
  - `SparseAttention/*`：计算稀疏化路线（固定稀疏、内容自适应、低秩、线性核）

## 3.1 新增论文时的分类复盘
- 无论是新增单篇论文，还是批量收录论文，都要先看目标主题下现有子目录是否仍然清晰。
- 若出现以下情况，应主动提出重分类建议：
  - 同一子目录下论文明显超过当前心智负担，难以快速浏览；
  - 同一目录中混入两种以上不同方法路线；
  - 新论文需要频繁写“暂时先放这里”，说明分类边界已经不稳定。
- 分类复盘至少回答三件事：
  - 这篇论文放进当前目录是否自然；
  - 是否值得拆出新的二级目录；
  - 是否需要同步更新对应“地图与综述”笔记，避免导航失真。

## 4. 自动组织优化（新增硬性要求）
当用户要求“搜集文章/收录论文/批量加入”时，必须自动执行以下动作：
1. 先扫描现有目录结构与地图笔记。
2. 给出一个“可执行的整理方案”，至少包含：
   - 论文 -> 目标目录映射
   - 是否需要新建/重命名目录
   - 每篇论文分类理由（一句话）
3. 在用户确认后执行迁移/新建。
4. 更新至少一处地图或总览入口（避免新增论文成为孤岛）。

若只是新增单篇论文，也至少要在交付中补一句分类判断：
- “沿用当前分类即可”，或
- “建议后续拆分为 X / Y 两类”，并说明原因。

## 5. 变更后校验
每次批量新增/迁移后，至少校验：
- 新文件 frontmatter 是否完整（尤其 `published`、`status`）。
- 若包含本地 PDF，检查该文件是否位于同级 `Attachments/` 目录中，而不是散落在主题目录根下。
- 目标目录中是否出现重复主题的冲突命名。
- 看板统计是否仍可按一级/二级目录聚合。

## 6. 交付格式约定
- 交付时先给“本次组织调整摘要”（新增目录、迁移文件数、保留不动项）。
- 再给“下一步建议”（可选），如：优先补读清单、按未读队列推进。

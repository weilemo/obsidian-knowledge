# A100 集群分区与存储：问答记录

## 问题

- 在 `a100_global` 跑和在对应 `a100_local_*` 上跑有什么区别？怎么设置？
- 我的数据放在 `/mnt` 和“在线节点”（本地盘）有没有区别？

## 回答要点（结论）

### 1) 分区差异

- **核心区别是调度范围**：
  - `a100_global`：在多台 A100 节点里任意调度。
  - `a100_local_*`：只会落到对应那 1 台节点（如 `a100_local_A100-0311-17100`）。
- **MaxTime / Priority / QoS 基本一致**，主要差异就是节点范围。

### 2) 如何设置

- 跑全局池：`-p a100_global`
- 锁定某台机器：`-p a100_local_<节点名>`
- 等价写法（在 global 上指定节点）：`-p a100_global -w <节点名>`

**示例**

```bash
# 交互（GPU，<=30分钟）
srun -p a100_global --gres=gpu:1 -t 00:30:00 --pty bash -l

# 锁定某台
srun -p a100_local_A100-0311-17100 --gres=gpu:1 -t 00:30:00 --pty bash -l

# 批处理（长任务）
sbatch -p a100_global --gres=gpu:4 -t 12:00:00 train.sh
```

### 3) `/mnt` 与本地盘的区别

- `/mnt` 是共享盘（网络存储），**所有节点都能看到同一路径**，便于复用与统一管理。
- **差异主要在性能**，不是“能不能访问”：
  - 共享盘有网络 I/O 竞争，高并发小文件读取会慢。
  - 节点本地盘（如 `/tmp`、本地 NVMe）通常更快，但不共享，作业结束可能丢失。

**实践建议**

- 数据集长期放 `/mnt`。
- 训练前把“热点小文件”预拷到本地临时目录再读（若节点有本地盘）。
- checkpoint 和最终结果回写 `/mnt`。

## 备注

> 以上结论是基于 `scontrol show partition a100_global` 等配置查看结果得出。

# 服务器工作习惯

## 一句话摘要
我在服务器上的默认工作方式是：**登录节点做轻量操作，计算任务统一通过 Slurm 提交，数据位置与分区选择保持一致，所有长任务都要有日志、可监控、可复现。**

## 核心工作规则

### 1. 任务统一走 Slurm，不在登录 shell 里长期裸跑

- 需要占用 CPU/GPU 的训练、推理、评测、批处理任务，默认用 `sbatch` 或 `srun`。
- 登录节点只做轻量操作：编辑代码、查看日志、提交作业、短时间调试。
- 不在登录 shell 里直接长期运行 Python/训练脚本，避免绕过调度器占用公共资源。

参考：
- [[A100集群Slurm用户手册_2026]]
- [[Slurm]]

### 2. 先判断数据在哪，再决定分区怎么选

- 数据在 `/mnt`：优先使用 `a100_global`。
- 数据在某台机器的 `/data` 或 `/data2`：使用对应的 `a100_local_<节点名>`，或显式指定 `--nodelist=<节点名>`。
- 不把“数据在哪”理解成 Slurm 会自动帮我选节点；真正决定调度的是我提交时写的分区和节点参数。

参考：
- [[A100集群Slurm用户手册_2026]]
- [[“数据在哪，作业就由哪个分区调度” 的准确解释]]

### 3. 正式任务显式写资源，不靠默认值

- 默认显式写清楚：分区、GPU 数量、CPU 数量、内存、时长、日志路径。
- 尽量按需申请资源，避免因为资源申请过大而排队太久。
- 正式项目作业显式指定 `--account <project_id>`，避免误进 `sandbox`。

最小模板：

```bash
#!/usr/bin/env bash
#SBATCH -J job_name
#SBATCH -p a100_global
#SBATCH --account your_project
#SBATCH --gres=gpu:1
#SBATCH -c 8
#SBATCH --mem=32G
#SBATCH -t 04:00:00
#SBATCH -o logs/%x-%j.out
#SBATCH -e logs/%x-%j.err

set -euo pipefail
mkdir -p logs

python3 your_script.py
```

### 4. 交互调试也要申请资源，不直接抢机器

- 需要进机器调试环境时，用 `srun ... --pty bash -l`。
- 进入交互环境后先看 `hostname` 和 `nvidia-smi`，确认自己在哪台机器、拿到了哪些 GPU。
- 调试结束立即 `exit`，释放资源。

示例：

```bash
srun -p a100_global --account your_project --gres=gpu:1 -c 8 --mem=32G -t 02:00:00 --pty bash -l
```

### 5. 每个长任务都必须可监控

- 提交后先记住 `jobid`。
- 用 `squeue` 看排队和运行状态。
- 用 `less +F` 或 `tail -f` 跟日志。
- 出现异常时先看 `scontrol show job <jobid>`，再判断是资源、优先级、节点还是脚本问题。

参考：
- [[Slurm 作业监控指南]]

### 6. 输出、日志、脚本要尽量可复现

- 提交脚本尽量保存到项目目录，不临时手敲完就丢。
- 日志按 `logs/%x-%j.out`、`logs/%x-%j.err` 这种模式保存，保证能回溯。
- 重要实验要能回答三个问题：
  - 用的是什么脚本？
  - 申请了什么资源？
  - 输出和报错日志在哪里？

### 7. 常驻服务不是默认工作方式

- 计算节点默认是跑作业的地方，不拿来长期挂 Web/API/守护进程。
- 如果确实需要常驻服务，先确认是否有专门的部署方式，而不是直接在计算节点后台挂着。

## 我的默认操作顺序

1. 先确认数据路径在 `/mnt` 还是某台机器的本地盘。
2. 根据数据位置选择 `a100_global` 或 `a100_local_<节点名>`。
3. 写好 `sbatch` 脚本，显式声明资源、账号和日志路径。
4. 提交后用 `squeue` 看状态。
5. 运行中跟踪 `out/err` 日志。
6. 有问题先看 `scontrol show job <jobid>` 和日志，再决定取消或重提。

## 提交前自检清单

- 我是不是误把长任务直接跑在登录 shell 里了？
- 我的数据路径和分区选择是否一致？
- 我有没有显式写 `--gres=gpu:N`、`-c`、`--mem`、`-t`？
- 正式任务有没有写 `--account`？
- 日志路径是否已经配置？
- 如果是交互调试，我是否设置了合理的资源和时长？

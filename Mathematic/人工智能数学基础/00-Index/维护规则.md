# 维护规则

这份规则用于后续持续维护这套学习系统，只保留长期反复会用到的约束。

## 规则 1
所有规划都要可执行、可推进，不为了“看起来完整”而堆任务。

具体含义：
- 不用自然周强行切分一切，但要保证推进节奏连续
- 每一个阶段都要有明确目标、完成标准、产出
- 每天的任务要足够小，能够真正执行
- 能拆成任务块，就不要只写大主题
- 能写完成标准，就不要只写“学懂”
- 能给自测题，就不要只写“复习一下”

## 规则 2
安排新的学习任务时，必须同时给出资源、内容说明和讲义。

具体含义：
- 每个任务块都尽量提供 `主线资源 + 补充资源`
- 如果资源暂时不合适，要显式写出“资源待补”
- `内容说明` 负责解释学什么、为什么学、最低完成标准是什么
- `讲义` 负责像 `02-Monthly/Month1/任务块C-讲义.md` 一样，把核心概念、公式、推导链条和直觉说明写完整
- 只给任务标题或任务清单，不算完成安排

## 规则 3
优先帮助建立“不容易忘”的学习系统。

具体含义：
- 每个阶段都应带有复习机制
- 每个知识点最好有回忆、手推、论文验证三种重复方式
- 不只关注“学了什么”，还关注“能不能记住并迁移到研究里”

## 规则 4
需要持续维护“学习进度”文档，并且与 `02-Monthly` 文件夹保持同步。

具体含义：
- 每安排过一个月 / 一个任务块，都应在进度文档里出现
- 每学过、跳过、补充过、调整过的内容，都应回写到进度文档
- 进度文档只负责记录学习推进，不负责评价学习质量
- 一律写 `YYYY-MM-DD`，不写“今天”“最近”“刚学完”
- `已建立内容` 只表示笔记、讲义、任务块已经搭好
- `已完成学习` 才表示该部分真的学过、做过输出或通过自测
- 如果只是调整结构、补资源、修改讲义，也应当记成“系统维护”，不要误写成学习完成
- 进度文档至少要记录：
  - 当前学到哪
  - 最近完成了什么
  - 下一步计划接什么

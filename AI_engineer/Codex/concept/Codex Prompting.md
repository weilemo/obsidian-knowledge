# Prompting
Interacting with the Codex agent

## Prompts
你通过“提示词”（用户消息）告诉 Codex 你想做什么。提交提示后，Codex 会循环执行：调用模型 → 执行动作（读/写文件、工具调用等）→ 直到完成或被你取消。

提示质量决定结果质量。页面给出两条核心建议：
- 让 Codex 可以“验证它的工作”，提供复现步骤、验证方式、lint 与 pre-commit 检查。
- 复杂任务拆成小步骤；不确定怎么拆时，让 Codex 先给计划。

## Threads
线程（thread）是一段完整会话：你的提示 + 模型输出 + 工具调用。一个线程里可以有多条提示（例如先实现功能，再追加测试）。

线程有两种运行位置：
- **Local 线程**：在你的机器上运行，可读写本地文件与执行命令；为降低风险，运行在沙箱中。
- **Cloud 线程**：在隔离环境中运行，会克隆仓库并检出正在工作的分支；适合并行或从另一设备委托任务。要用 Cloud 线程，需先把代码推到 GitHub，也可以把本地线程委托到云端（包含当前工作状态）。

提示：可以并行多个线程，但避免同时修改同一文件；线程也可以稍后续接。

## Context
提交提示时应附上 Codex 需要的上下文，比如相关文件或图片。IDE 扩展会自动附上“打开的文件列表”和“选中代码范围”。

在执行过程中，Codex 还会从文件内容、工具输出、以及任务记录中收集上下文。所有信息必须放进模型上下文窗口。对于长任务，Codex 会自动压缩上下文（总结关键内容、丢弃不重要细节），并在多次压缩后继续完成复杂任务。

## 1. 项目目标

本项目要求在 Logisim Evolution 中实现一个简化的 RISC-V CPU。CPU 需要支持一组常用 RV32I/RV32M 指令，包括算术逻辑运算、立即数运算、访存、条件分支、跳转以及 `tohost` CSR 写入。

整体设计采用两级流水线：

1. IF 阶段：根据当前 PC 从指令存储器取指。
2. EX 阶段：完成译码、寄存器读取、ALU 运算、访存控制、写回、分支跳转决策和 CSR 写入。

这样做的核心是把取指和执行分开，并在两个阶段之间加入指令寄存器和 PC 寄存器，使 CPU 每个周期都能推进一条指令。

## 2. ALU 设计

ALU 接收两个 32 位输入 `A`、`B`，以及 4 位控制信号 `ALUSel`，输出 32 位 `Result`。实现时的思路是：所有候选运算并行计算，最后用一个多路选择器根据 `ALUSel` 选择输出。

主要操作包括：

| `ALUSel` | 操作 | 说明 |
|---|---|---|
| 0 | `add` | `A + B` |
| 1 | `and` | 按位与 |
| 2 | `or` | 按位或 |
| 3 | `xor` | 按位异或 |
| 4 | `srl` | 逻辑右移 |
| 5 | `sra` | 算术右移 |
| 6 | `sll` | 左移 |
| 7 | `slt` | 有符号小于比较 |
| 10 | `mul` | 乘积低 32 位 |
| 11 | `mulhu` | 无符号乘积高 32 位 |
| 12 | `sub` | `A - B` |
| 13 | `bsel` | 直接输出 `B` |
| 14 | `mulh` | 有符号乘积高 32 位 |

移位类指令只使用 `B` 的低 5 位作为移位量，因为 RV32 中 32 位数据的移位范围是 0 到 31。乘法类指令通过 64 位乘积再截取高低部分实现。

## 3. 寄存器堆设计

寄存器堆包含 32 个 32 位寄存器，对应 RISC-V 的 `x0` 到 `x31`。它有两个读端口和一个写端口：

- `Read Register 1` 输出 `rs1`
- `Read Register 2` 输出 `rs2`
- `Write Register` 和 `Write Data` 用于写回
- `RegWEn` 控制是否写入

关键约束是 `x0` 必须恒为 0。因此写入逻辑中需要屏蔽 `rd = 0` 的情况：

$$
\text{write\_enable}_i = \text{RegWEn} \land (rd = i) \land (i \ne 0)
$$

读端口通过 32 路选择器根据寄存器编号选择输出。为了配合作业测试，还额外暴露了 `ra`、`sp`、`t0`、`t1`、`t2`、`s0`、`s1`、`a0` 等调试输出。

## 4. 立即数生成器设计

立即数生成器根据 `ImmSel` 从 32 位指令中取出对应格式的立即数，并符号扩展到 32 位。

支持的立即数类型包括：

| 类型 | 指令例子 | 立即数字段 |
|---|---|---|
| I-type | `addi`, `lw`, `jalr` | `inst[31:20]` |
| S-type | `sw`, `sb`, `sh` | `inst[31:25]` 与 `inst[11:7]` |
| B-type | `beq`, `blt` | `inst[31]`, `inst[7]`, `inst[30:25]`, `inst[11:8]`, 末位补 0 |
| U-type | `lui`, `auipc` | `inst[31:12]` 后接 12 个 0 |
| J-type | `jal` | `inst[31]`, `inst[19:12]`, `inst[20]`, `inst[30:21]`, 末位补 0 |

所有需要符号扩展的立即数都使用最高有效位作为符号位。例如 I-type 立即数：

$$
\text{imm}_I = \text{SignExt}(inst[31:20])
$$

B-type 和 J-type 的最低位固定为 0，是因为分支和跳转偏移以 2 字节对齐编码。

## 5. 分支比较器设计

分支比较器输入 `rs1`、`rs2` 和 `BrUn`，输出：

- `BrEq`: 两个操作数是否相等
- `BrLt`: `rs1` 是否小于 `rs2`

其中 `BrUn = 0` 时执行有符号比较，`BrUn = 1` 时执行无符号比较。这样 `blt`、`bge` 使用有符号比较，`bltu`、`bgeu` 使用无符号比较。

分支决策由控制逻辑结合 `funct3`、`BrEq` 和 `BrLt` 完成。例如：

| 指令 | 跳转条件 |
|---|---|
| `beq` | `BrEq = 1` |
| `bne` | `BrEq = 0` |
| `blt` / `bltu` | `BrLt = 1` |
| `bge` / `bgeu` | `BrLt = 0` |

## 6. 控制逻辑设计

控制逻辑根据 `opcode`、`funct3`、`funct7` 识别指令，并生成数据通路所需的控制信号。整体采用硬连线控制，而不是 ROM 控制。

主要控制信号包括：

| 控制信号 | 作用 |
|---|---|
| `PCSel` | 选择下一条 PC，是 `PC + 4` 还是分支/跳转目标 |
| `ImmSel` | 选择立即数格式 |
| `RegWEn` | 是否写回寄存器 |
| `BrUn` | 是否使用无符号分支比较 |
| `ASel` | ALU 输入 A 选择 `rs1` 或 `PC` |
| `BSel` | ALU 输入 B 选择 `rs2` 或立即数 |
| `ALUSel` | 选择 ALU 操作 |
| `MemRW` / `Write_En` | 控制数据内存写入 |
| `WBSel` | 写回数据来源：ALU、内存、`PC + 4` 等 |
| `CSR_WE` | 是否写入 `tohost` CSR |

不同类型指令的数据流如下：

- R-type：`rs1` 和 `rs2` 进入 ALU，结果写回 `rd`。
- I-type 算术：`rs1` 和立即数进入 ALU，结果写回 `rd`。
- Load：ALU 计算地址，内存读出后按字节/半字/字扩展，再写回 `rd`。
- Store：ALU 计算地址，`rs2` 提供写入数据，控制逻辑生成字节写掩码。
- Branch：比较 `rs1` 和 `rs2`，若条件满足，则下一 PC 选择 `PC + imm`。
- `jal` / `jalr`：写回 `PC + 4`，同时修改 PC。
- `lui`：直接写回 U-type 立即数。
- `auipc`：写回 `PC + imm`。
- CSR：将寄存器值或 uimm 写入 `tohost`。

## 7. CPU 数据通路

CPU 主数据通路可以分为以下几条关键路径。

### 7.1 取指路径

PC 寄存器保存当前取指地址。正常情况下：

$$
PC_{\text{next}} = PC + 4
$$

当分支或跳转发生时：

$$
PC_{\text{next}} = PC_{\text{EX}} + imm
$$

对于 `jalr`，目标地址来自寄存器加立即数：

$$
PC_{\text{next}} = rs1 + imm
$$

### 7.2 执行路径

指令进入 EX 阶段后，先拆分出 `opcode`、`rd`、`funct3`、`rs1`、`rs2`、`funct7` 等字段。寄存器堆读出 `rs1` 和 `rs2`，立即数生成器产生 `imm`。然后通过 `ASel` 和 `BSel` 选择 ALU 输入。

典型 ALU 输入选择是：

| 指令类型 | ALU A | ALU B |
|---|---|---|
| R-type | `rs1` | `rs2` |
| I-type | `rs1` | `imm` |
| Load/Store | `rs1` | `imm` |
| Branch/JAL/AUIPC | `PC` | `imm` |
| LUI | 0 或任意 | `imm` |

### 7.3 写回路径

写回数据由 `WBSel` 选择：

- ALU 结果：算术逻辑、地址计算、`lui`、`auipc`
- 内存读出数据：`lb`、`lh`、`lw`
- `PC + 4`：`jal`、`jalr`

写回前还要保证 `RegWEn = 1` 且 `rd != x0`。

## 8. 两级流水线与控制冒险

本项目采用 IF/EX 两级流水线。IF 阶段取出的指令不会立即执行，而是在下一个周期进入 EX 阶段。因此需要在阶段之间保存：

- IF 阶段取到的指令
- 该指令对应的 PC

分支和跳转在 EX 阶段才知道是否改变 PC。此时 IF 阶段已经取出了下一条顺序指令。如果当前 EX 指令发生跳转，则 IF 阶段取到的顺序指令是错误的，需要 kill。

kill 的实现方式是把进入执行阶段的下一条指令替换为 `nop`：

$$
\text{nop} = 0x00000013
$$

也就是：

```asm
addi x0, x0, 0
```

这样错误取出的指令不会修改寄存器、内存或 CSR。

## 9. 内存访问设计

作业中的数据内存是外部提供的，CPU 只输出：

- `WRITE_ADDRESS`
- `WRITE_DATA`
- `WRITE_ENABLE`

Load 指令需要从 `READ_DATA` 中取出对应字节或半字，并进行符号扩展：

$$
lb: \text{SignExt}(\text{selected byte})
$$

$$
lh: \text{SignExt}(\text{selected halfword})
$$

$$
lw: \text{READ\_DATA}
$$

Store 指令根据地址低两位生成字节写使能。例如 `sb` 只打开一个字节 lane，`sh` 打开两个字节 lane，`sw` 打开全部四个字节 lane。作业约定只考虑对齐访问，因此不实现跨 word 的非对齐访存。

## 10. CSR 设计

CSR 部分只需要实现 `tohost = 0x51E`。当指令是：

```asm
csrw tohost, rs1
```

或：

```asm
csrwi tohost, uimm
```

并且 CSR 地址等于 `0x51E` 时，打开 `CSR_WE`，在时钟上升沿写入 `tohost` 寄存器。测试框架通过观察 `tohost` 判断程序是否结束或是否成功。

## 11. 测试策略

测试分为三层。

第一层是单元测试：

- ALU 测试每个 `ALUSel` 是否正确。
- RegFile 测试普通读写、全寄存器读写和 `x0` 恒为 0。

第二层是基础 CPU 测试：

- `addi_pipelined` 验证两级流水线下的基本写回。
- `part_b/pipelined` 验证算术、分支、跳转、内存和 CSR。

第三层是自定义测试：

- 对每条主要指令单独写 `.s` 文件。
- 用 Venus 生成机器码和参考输出。
- 再由 Logisim 跑 CPU 输出，与参考输出比较。

## 12. 总结

本设计的核心思路是：先实现可靠的基础部件 ALU、RegFile、ImmGen 和 Branch Comparator，再用硬连线控制把不同类型 RISC-V 指令映射到同一条数据通路上。CPU 主体采用两级流水线，因此必须保存 IF/EX 之间的指令和 PC，并在分支或跳转发生时用 `nop` 清除错误取到的指令。

相比单周期 CPU，两级流水线的数据通路并没有本质变化，主要新增复杂性来自 PC 时序和控制冒险处理。只要保证写回、访存、CSR 写入等有副作用的信号在 `nop` 或错误路径下关闭，就可以使流水线行为与参考输出一致。

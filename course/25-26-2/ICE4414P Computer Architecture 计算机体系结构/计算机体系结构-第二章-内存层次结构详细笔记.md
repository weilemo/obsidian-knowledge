# 计算机体系结构（Chapter 2）- 内存层次结构详细笔记

来源课件：
- `chapter2-part1.pdf`

## 1. 第二章主线

第二章的核心问题是：

1. 处理器很快、主存较慢，如何缩小 CPU-Memory Gap。  
2. 通过多级缓存（L1/L2/L3）和虚拟内存，把“快小贵”和“慢大便宜”组合起来。  
3. 在性能、功耗、面积、复杂度之间做体系结构权衡。

## 2. 局部性与内存层次

### 2.1 局部性原理

1. 时间局部性（Temporal Locality）：最近访问过的数据很可能再次访问。  
2. 空间局部性（Spatial Locality）：与当前地址相邻的数据很可能很快被访问。

缓存能工作的根本原因是程序普遍具有局部性。

可以把局部性理解成程序访问内存时的“偏心”：

1. 它不会均匀访问整个地址空间。  
2. 它往往会在某个小范围里反复活动。  

例如循环中的变量、栈顶数据、顺序执行的指令流，都天然体现了局部性。  
体系结构设计者正是利用这种偏心行为，才敢把一个容量较小但速度很快的缓存放在处理器附近。

### 2.1.1 两类局部性的典型例子

1. 时间局部性：循环计数器、最近访问的数组元素、被频繁调用的函数入口。  
2. 空间局部性：数组顺序遍历、顺序取指、结构体内部连续字段访问。  

这也是为什么：

1. 重复使用的数据适合留在 cache 中。  
2. 相邻数据适合整块搬运，而不是一次只搬一个字。  

### 2.2 SRAM 与 DRAM 的角色

1. SRAM：速度快、面积大、成本高，常用于寄存器和片上 Cache。  
2. DRAM：速度慢于 SRAM、密度高、成本低，常用于主存。

因此形成层次：寄存器 -> L1 -> L2 -> L3 -> DRAM -> 外存。

这条层次链本质上是在做折中：

1. 越靠近 CPU，越快，但容量越小、价格越高。  
2. 越远离 CPU，容量越大、单比特更便宜，但访问延迟越高。  

所以第二章的核心不是“如何找到一种最好的存储器”，而是“如何把不同特性的存储器组织成一个层次系统”。

## 3. Cache 基础模型

### 3.1 关键术语

1. Hit：在上层（例如 L1）找到数据块。  
2. Miss：上层没找到，需要去下一层。  
3. Hit Time：命中访问时间。  
4. Miss Ratio：未命中比例。  
5. Miss Penalty：发生 miss 时的额外代价。

这里有一个很重要的理解：

1. `Hit Time` 不是访问整个层次结构的时间，而是“上层自己”的访问时间。  
2. `Miss Penalty` 不是简单的下层访问时间，而是从 miss 发生到数据真正可用所增加的总成本。  

因此，第二章所有优化几乎都可以归结为在三个指标之间做文章：

1. 降低 hit time  
2. 降低 miss ratio  
3. 降低 miss penalty  

### 3.2 平均访问时间（AMAT）

单级缓存：

$$
AMAT = t_{hit} + m \times p_{miss}
$$

课件常见写法：

$$
t_{avg} = t_{cache} + \text{miss ratio} \times t_{memory}
$$

多级缓存（两级示意）：

$$
AMAT = t_{L1} + m_{L1}\times (t_{L2} + m_{L2}\times p_{L2})
$$

这个公式特别重要，因为它直接告诉我们：

1. L1 访问再快，如果 miss 太多，整体仍然会慢。  
2. L1 miss 不一定是灾难，只要 L2 足够快也能接受。  
3. 某项优化不能只看单个指标，而要看它对整个 AMAT 的影响。  

例如：

1. 增大 cache 可能降低 miss ratio。  
2. 但它也可能提高 hit time。  

到底值不值，不能凭直觉，要回到 AMAT 看净效果。

### 3.3 命中率与未命中率的直觉

1. Hit rate 高，说明大多数请求在上层就解决了。  
2. Miss rate 低，说明下层很少被访问。  

但在工程上不能只盯着 miss rate，因为：

1. 某些优化虽然只把 miss rate 降了一点，却能显著减小 miss penalty。  
2. 另一些优化虽然让 miss rate 更低，却把 hit time 拉长了。  

所以课件中一直强调 memory hierarchy 是一个系统问题，而不是某个单参数问题。

## 4. Cache 的三大参数与权衡

### 4.1 Cache Size（容量）

1. 容量增大通常降低 miss rate（更好利用时间局部性）。  
2. 但容量过大可能增加 hit time、功耗和成本。

容量为什么能降 miss，很好理解：

1. 能留下更多最近访问过的数据。  
2. 数据被替换出去得更慢。  

但容量增大也会带来现实代价：

1. 更大的 tag/data array 访问路径更长。  
2. 比较器、位线、字线更复杂。  
3. 功耗和芯片面积上升。  

所以现实系统通常会把 L1 做得小而快，把更大的容量放到 L2/L3。

### 4.2 Block Size（块大小）

1. 块变大可利用空间局部性，降低强制性 miss。  
2. 块太大时会带来更高 miss penalty，并可能挤占有效缓存容量导致 miss 上升。

块大小是第二章里最典型的 trade-off 之一：

1. 块太小：空间局部性利用不足，每次 miss 只带回很少信息。  
2. 块太大：一次搬回来太多“暂时用不到”的数据，浪费带宽，也减少可容纳的块数。  

因此，块大小没有绝对最优值，它取决于：

1. 程序的空间局部性强不强。  
2. cache 容量有多大。  
3. 下层内存的带宽和延迟特性。  

### 4.3 Associativity（相联度）

1. 直接映射（Direct-mapped）：快、简单，但冲突 miss 较多。  
2. 组相联（Set-associative）：冲突 miss 更少，但 hit latency 增加。  
3. 全相联（Fully associative）：冲突最少，硬件代价最高。

经验法则（课件常见）：更高相联度可降冲突 miss，但访问关键路径变长。

相联度控制的是“一个内存块有多少个候选位置可以放”。

1. 直接映射：只有一个位置，找起来最快，但容易冲突。  
2. 全相联：哪里都能放，冲突最少，但查找要比对所有 tag。  
3. 组相联：介于两者之间。  

第二章课件很喜欢考的就是这类理解题：

1. 直接映射为什么快。  
2. 为什么提高相联度能降低 conflict miss。  
3. 为什么相联度不能无限提高。  

答案都围绕一个核心：  
**更自由的放置能力换来更复杂的查找代价。**

## 5. 映射、替换与写策略

### 5.1 基本问题（课件框架）

1. 块放哪里（placement）？  
2. 怎么找（identification/tag）？  
3. miss 时替换谁（replacement）？  
4. 写操作怎么处理（write policy）？

这四个问题可以看成是 cache 设计的标准模板。  
以后看到任何 cache 结构，无论是 TLB、victim cache 还是 page cache，都可以先用这四问去拆解。

### 5.2 替换策略

1. LRU：更贴合时间局部性，硬件开销较高。  
2. FIFO：简单，效果次于 LRU 的场景较多。  
3. 伪LRU：在复杂度和效果之间折中。

替换策略回答的是：当 set 已经满了，新块来了该踢谁出去。

1. LRU 的直觉是：最近最久没用的块，以后大概率也更不重要。  
2. FIFO 不关心最近是否用过，只看进入 cache 的先后顺序。  

在小相联度 cache 中，LRU 往往效果更好；但相联度变高后，精确实现 LRU 的硬件开销会变得不划算，因此工程上常用近似策略。

### 5.3 写策略

1. Write-through：每次写都更新下层，简单但写流量大。  
2. Write-back：只在替换时回写，流量小但控制复杂。  
3. Write-allocate：写 miss 时先装入 cache，再写。  
4. No-write-allocate：写 miss 直接写下层，不装入 cache。

常见搭配：Write-back + Write-allocate；Write-through + No-write-allocate。

写策略之所以比读策略更麻烦，是因为写会引出“上层和下层谁才是最新版本”的问题。

1. Write-through：优点是简单，下层始终保持最新；缺点是每次写都会带来流量。  
2. Write-back：优点是大幅减少写流量；缺点是必须用 dirty bit 记录哪些块被修改过。  

是否分配（allocate）则体现另一种取舍：

1. 如果写 miss 后很快还会继续访问该块，那么 write-allocate 更划算。  
2. 如果只是偶发写一次，直接写下层可能更省事。  

所以写策略本质上是在平衡：

1. 写流量  
2. 一致性管理复杂度  
3. 后续访问的局部性  

### 5.4 写缓冲（Write Buffer）

写缓冲可隐藏写延迟、减少阻塞；但会引入读写顺序与一致性相关复杂性。

写缓冲的直觉很像“待办队列”：

1. 处理器先把写请求放进去。  
2. 自己不用每次都等写入下层完成再继续。  

这能显著改善 write-through cache 的性能。  
但问题在于：如果后面一条读刚好要读写缓冲里尚未真正落到内存的数据，就必须额外检查写缓冲内容。

这也是为什么课件会强调“读优先于写”“检查 write buffer”这类优化。

## 6. Miss 分类与优化方向

### 6.1 3C/4C 分类

1. Compulsory Miss：首次访问导致。  
2. Capacity Miss：容量不够导致。  
3. Conflict Miss：映射冲突导致。  
4. Coherence Miss（多核场景）：一致性失效导致。

这个分类很重要，因为不同类型 miss 的解决方案完全不同：

1. Compulsory miss：可以靠更大块、预取来缓解。  
2. Capacity miss：主要靠更大 cache 或更好的程序局部性。  
3. Conflict miss：主要靠更高相联度、victim cache、数据布局优化。  
4. Coherence miss：主要靠一致性协议与共享数据访问模式优化。  

也就是说，看到 miss 变多，第一步不是盲目“把 cache 加大”，而是先判断它属于哪一类。

### 6.2 常见优化手段

1. 增大容量、提高相联度（降低 miss rate）。  
2. 多级缓存（降低 miss penalty）。  
3. Critical-word-first / Early restart（降低有效 miss penalty）。  
4. Nonblocking cache（支持 miss 下命中，提升并行性）。  
5. Multibanked cache（提升带宽）。  
6. Victim cache、Pseudo-associative cache（降低冲突 miss）。  
7. 读优先于写（降低读 miss 受写缓冲阻塞）。

这些优化可以按“目标”来重新整理：

1. 为了更快命中：小而简单的 L1、较低相联度、并行路径优化。  
2. 为了更少 miss：更大容量、更高相联度、victim cache、程序变换。  
3. 为了 miss 以后损失更小：多级 cache、critical word first、prefetch、nonblocking cache。  
4. 为了每单位时间服务更多请求：多 bank、流水化 cache、写缓冲。  

这种分类方式很适合考试时做归纳题。

## 7. 预取（Prefetching）

### 7.1 核心思想

在处理器真正请求前，提前把可能用到的数据搬近。

预取其实是在做一件很大胆的事：  
**在还没确定需要之前，先花资源把数据搬过来。**

所以预取总是带着风险：

1. 猜对了，就把长延迟提前隐藏掉。  
2. 猜错了，就浪费带宽、占空间、甚至把真正有用的数据挤出去。  

### 7.2 类型

1. 硬件预取：通过访问模式自动预测。  
2. 软件预取：编译器/程序员插入 prefetch 指令。

两者优缺点可以这样记：

1. 硬件预取：对程序透明，自动化强，但硬件复杂、预测未必准确。  
2. 软件预取：可利用编译器语义信息，但依赖编译质量，也可能对不同输入不够稳。  

### 7.3 预取是否有效的判断

预取要满足“收益 > 成本”：

1. 预取命中率要高（准确）。  
2. 预取要足够早但不过早（及时）。  
3. 不能过度占用带宽或污染 cache。

这里最常见的失败模式有三种：

1. 太晚：等于没预取到。  
2. 太早：数据先到了，但在真正用到前又被挤掉。  
3. 太多：把内存带宽和 cache 空间都占满，拖累正常请求。  

所以预取不是“越积极越好”，而是一个很精细的平衡问题。

## 8. 软件层面的 Cache 优化（课件强调）

1. 循环分块（Blocking/Tiling）：提高时间局部性。  
2. 合并数组/结构调整：改善空间局部性。  
3. 过程重排、数据布局优化：减少冲突 miss。  
4. 按缓存友好顺序访问（如行优先匹配存储布局）。

第二章强调软件优化，说明 cache 性能不只是硬件问题。  
程序访问模式本身就决定了局部性质量。

例如矩阵运算中：

1. 如果按内存连续方向访问，就更容易形成空间局部性。  
2. 如果把工作集切成能装进 cache 的小块反复处理，就能提高时间局部性。  

所以软件层优化的本质是：  
**主动把程序访问模式改造成更适合 cache 的形状。**

## 9. 虚拟内存（Virtual Memory）

### 9.1 设计目标

1. 让程序看到更大地址空间。  
2. 提供保护与隔离。  
3. 用主存作为磁盘的 cache（按页管理）。

虚拟内存与前面 cache 的思想其实一脉相承：  
都是利用局部性，让上层看起来像拥有一个又大又快的存储空间。

不同的是：

1. 普通 cache 在“CPU 和主存”之间。  
2. 虚拟内存在“主存和磁盘”之间。  

因此虚拟内存 miss 的代价远远大于普通 cache miss。

### 9.2 基本对象

1. Page（页）：虚拟内存传输与管理单位。  
2. Page Table（页表）：维护虚拟页到物理页映射。  
3. TLB：页表项的高速缓存，加速地址翻译。

可以把它们理解成三层角色：

1. Page：搬运和管理的基本块。  
2. Page Table：正式账本，记录映射关系。  
3. TLB：账本的快取，避免每次都去查完整页表。  

### 9.3 地址转换

$$
\text{Virtual Address} = \text{VPN} + \text{Page Offset}
$$

$$
\text{Physical Address} = \text{PPN} + \text{Page Offset}
$$

页内偏移在转换前后不变；TLB 命中时可快速得到 PPN。

这个“不变”非常关键，因为它解释了很多 cache 和 TLB 的并行设计约束：

1. 页面内的位置没变。  
2. 所以只要 cache 索引位来自 page offset，就可以在地址翻译完成前先做一部分 cache 访问。  

这正是后面 VIPT 等设计思路的基础。

### 9.4 TLB 与 Cache 交互

1. 串行方式：先 TLB 翻译，再 Cache 访问（简单但慢）。  
2. 并行方式：TLB 与 Cache 并行（快但有 VIPT 约束）。

常见约束：Cache 的索引位尽量来自 page offset，避免同义地址别名问题（aliasing）。

这一节的核心不是背缩写，而是理解为什么地址翻译会拖慢 cache 访问：

1. cache 需要地址来索引和比 tag。  
2. 但虚拟地址先要翻译成物理地址。  
3. 这就可能把“本来很快的 L1 命中路径”拉长。  

因此体系结构设计者要想办法让：

1. 地址翻译尽量不拖慢 L1。  
2. 同时又不引入同义地址、保护检查错误等问题。  

这是 cache 和虚拟内存交汇处最重要的设计难点之一。

## 10. 第二章常考公式与结论速记

1. 单级 AMAT：

$$
AMAT=t_{hit}+m\times p_{miss}
$$

2. 多级 AMAT（两级）：

$$
AMAT=t_{L1}+m_{L1}\times (t_{L2}+m_{L2}\times p_{L2})
$$

3. 提升缓存性能的三条主线：  
- 降低 hit time  
- 降低 miss rate  
- 降低 miss penalty

4. 体系结构本质是 trade-off：  
更大、更高相联、更复杂机制通常能降 miss，但会增加 hit 延迟、能耗和实现复杂度。

## 11. 第二章常见易混点

### 11.1 Hit Time 和 Miss Penalty

1. Hit time 是上层命中时花的时间。  
2. Miss penalty 是 miss 后额外多花的时间。  

不要把下层访问时间简单等同于 miss penalty，因为实际还包括传输、仲裁、恢复等成本。

### 11.2 直接映射更快，不代表一定更好

直接映射结构简单、hit time 小，但 conflict miss 容易偏高。  
是否更优，取决于程序访问模式。

### 11.3 Cache 更大，不代表系统一定更快

更大 cache 能降 miss，但也可能：

1. 增加 hit time  
2. 增加能耗  
3. 增加设计复杂度  

最终还是要回到 `AMAT` 和整体系统目标来判断。

### 11.4 虚拟内存不是“更大的 RAM”

它是一个地址抽象和保护机制，同时把主存当作磁盘的 cache。  
它的意义不只是扩容，还包括隔离、保护和程序装载便利性。

## 12. 一句话总结

第二章的本质是：利用局部性构建多级存储体系，并通过“参数设计 + 硬件机制 + 软件优化 + 虚拟内存协同”把平均访存成本压低。

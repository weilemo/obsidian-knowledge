## 模板与const机制知识地图

本节不是按提问顺序整理，而是按 C++ 的语法机制和本质关系组织。

### 类型层：类模板、具体类、对象

#### `arr` 与 `elemType` 的关系
```cpp
template <class elemType>
class arr { ... };
```
- `arr` 是类模板名（通用蓝图）。
- `elemType` 是类型参数（占位符）。
- `arr<int>`、`arr<double>` 是实例化后的具体类。
- 对象是具体类的实例，例如 `arr<int> obj1(10);`。

#### 类模板的典型写法（类外实现）
```cpp
template <class T>
class Arr {
public:
    Arr(int n);
    void find(const T& x) const;
};

template <class T>
Arr<T>::Arr(int n) { ... }

template <class T>
void Arr<T>::find(const T& x) const { ... }
```
- 类外定义成员函数时，函数前必须再写一次 `template <class T>`。
- 作用域要写成 `Arr<T>::`。

### 封装层：`private` / `public` 与“成员”概念

#### 为什么叫成员
写在类大括号里的变量和函数都叫成员：
- 成员变量（如 `a`, `maxSize`, `count`）
- 成员函数（如构造函数、`append`、`find`）

#### `private` 和 `public` 的本质
- `private`：只允许类内部访问（保护内部状态）。
- `public`：作为对外接口给外部调用。

常见设计：
- 数据放 `private`，防止随意破坏结构不变量。
- 操作函数放 `public`，控制合法访问路径。

### `const` 系统：参数只读 vs 对象只读

对于声明：
```cpp
void find(const elemType &x) const;
```
有两个不同位置的 `const`：

#### 参数位置 `const elemType &x`
- `&` 表示引用，`x` 是实参别名。
- `const` 表示函数内不能修改 `x`。
- 好处：不拷贝大对象，降低开销。

#### 函数末尾 `... ) const`
- 这是成员函数 `const`，约束的是调用对象 `*this`。
- 含义：该函数承诺不修改对象状态。

#### 常对象与非常对象的调用规则
- 常对象（`const arr<int> obj2`）只能调用 `const` 成员函数。
- 非常对象（`arr<int> obj1`）两类函数都可调用。

### 引用与拷贝构造：何时发生拷贝

#### 为什么 `const T&` 通常不触发拷贝构造
- 按值传参 `T x` 需要构造形参副本。
- 引用传参 `const T& x` 绑定到已有对象，通常不产生副本对象。

#### “形参不分配空间”的准确理解
课堂表述“形参不分配空间”是简化说法，更准确地说：
- 不会为“一个新的 `T` 副本对象”分配对象存储。
- 实现上仍会维护引用绑定关系。

#### 何时拷贝、何时不拷贝（实用规则）
- 小类型（`int`/`double`）常按值传递。
- 大对象（`string`/`vector`/自定义类）优先 `const T&`。
- 需要修改调用者对象时用 `T&`。

### 对象模型层：`this`、静态成员、非静态成员

#### `this` 的本质
- `this` 是非静态成员函数的隐含参数。
- `this->head = last;` 表示给“当前对象的 `head` 成员”赋值。
- `this` 不是对象里单独存的一个普通字段，而是调用时传入的当前对象地址语义。

#### 静态成员 vs 非静态成员
- 非静态成员：属于对象，每个对象各有一份。
- 静态成员：属于类，所有对象共享一份。
- 静态成员函数没有 `this`，不能直接访问非静态成员。

### 抽象机制层：抽象类、非抽象类、继承与模板

#### 抽象类和非抽象类
- 含纯虚函数（`=0`）的是抽象类，不能直接实例化。
- 实现了所有纯虚函数的是非抽象类，可实例化。

#### 与模板的关系
- 模板解决“同一逻辑适配不同类型”。
- 继承/抽象类解决“同一接口的不同实现”。
- 二者可组合：例如 `queue<T>` 抽象接口 + `seqQue<T>` / `linkQue<T>` 两种实现。

### 数据结构落地层：链式存储的构成原理

#### 基本构成
- 结点 `Node<T>` 包含 `data` 和 `next`。
- 通过指针把离散结点串成逻辑线性结构。
- 从 `head` 出发沿 `next` 遍历。

#### `find` 的本质
- 线性扫描：`p = head`，逐结点比较 `p->data`。
- 时间复杂度通常为 `O(n)`。

#### 课堂示例中的实现风险（理解代码质量）
- 若构造函数额外挂了一个未赋值尾结点，而 `find` 又遍历到 `NULL`，就可能读到未初始化数据。
- 这提醒我们：模板语法正确不等于实现一定严谨，数据结构代码还要检查边界与结点生命周期。

### 一页速记（考试/作业前）
- `template<class T> class A`：T 是类型占位符。
- `private` 管状态，`public` 管接口。
- `const T&`：只读参数 + 避免拷贝。
- `func(...) const`：不改调用对象，常对象可调。
- `this->m`：当前对象成员。
- 静态成员属于类，非静态成员属于对象。
- 抽象类定义接口，子类给实现；模板给类型复用。
- 链式存储靠 `next` 连接，查找常是 `O(n)`。

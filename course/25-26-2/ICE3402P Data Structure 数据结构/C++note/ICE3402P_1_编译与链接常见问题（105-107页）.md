### 第105页：`std` 命名空间与 `ostream` 提示

高频现象：
- 写了 `ostream`、`cout`、`cin`，编译器报“未声明标识符”。

原因：
- 这些名字在命名空间 `std` 里，直接写裸名字可能找不到。

两种常见写法（选一种保持一致）：

#### 写法A：显式加 `std::`
```cpp
#include <iostream>

int main() {
    std::cout << "hello" << std::endl;
    return 0;
}
```

#### 写法B：引入名字（或命名空间）
```cpp
#include <iostream>
using std::cout;
using std::endl;

int main() {
    cout << "hello" << endl;
    return 0;
}
```

备注：
- 初学阶段可用 `using namespace std;`，但工程代码更推荐“局部引入名字”或显式 `std::`。

### 第106页：`undefined reference` 是什么

高频现象：
- 编译通过，但链接阶段报：`undefined reference to ...`

本质：
- 声明看到了，定义没找到（链接器找不到函数/变量实体）。

常见原因与修复：

1. **只声明没定义**
```cpp
int add(int a, int b); // 声明了
// 但没有 add 的函数体
```
修复：补上函数定义。

2. **签名不一致（声明和定义不完全匹配）**
- 例如一个写 `int f(int)`，另一个写 `int f(const int&)`。
修复：保证返回类型、参数类型、`const` 修饰完全一致。

3. **模板函数/模板类实现放在 .cpp 导致实例化找不到**
修复：
- 把模板实现放回头文件（或同一翻译单元），避免链接期缺失实例。

4. **多文件编译时漏了源文件**
修复：
- 编译命令里把相关 `.cpp` 都带上。

5. **类静态成员变量只声明未定义**
```cpp
class A { public: static int cnt; };
// 还需要在类外定义：int A::cnt = 0;
```

### 第107页：`#include` 两种写法

#### 1) `#include <...>`
- 主要用于系统/标准库头文件。
- 例如：
```cpp
#include <iostream>
#include <vector>
```

#### 2) `#include "..."`
- 主要用于当前项目/自定义头文件。
- 例如：
```cpp
#include "arr.h"
#include "Node.hpp"
```

查找路径直观理解：
- `<...>`：优先系统头文件路径。
- `"..."`：优先当前工程路径，再到系统路径。

---

### 一页速记
- `cout/cin/ostream` 常在 `std` 命名空间中。
- `undefined reference` = 链接期找不到定义，不是语法错误。
- 模板实现尽量与声明放同一头文件，避免链接缺定义。
- `#include <...>` 常用于标准库，`#include "..."` 常用于自定义头文件。

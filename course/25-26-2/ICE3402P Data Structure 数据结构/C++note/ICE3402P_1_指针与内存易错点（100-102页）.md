# ICE3402P_1 指针与内存易错点（第100-102页）

- 来源文件：`ICE3402P_1.pdf` 第 100-102 页
- 整理目标：围绕指针、delete、链表连接陷阱的高频错误排查

## 指针与内存易错点

### 第100页：赋值与取地址的基本规则

#### 错误1：未初始化指针就解引用
```cpp
int *p;
*p = 1; // 错误：p 是野指针
```
原因：`p` 没有指向合法对象，解引用会访问随机内存。

正确写法示例：
```cpp
int x = 1;
int *p = &x;
// 或
int *q = new int(1);
```

#### 错误2：对字面量取地址
```cpp
int *p;
p = &1; // 错误
```
原因：字面量 `1` 不是可取地址的左值对象。

### 第101页：`delete` 的四类典型错误

#### 错误1：释放未初始化指针
```cpp
int *p;
delete p; // 错误
```

#### 错误2：重复释放（double free）
```cpp
int *p = new int[100];
delete[] p;
delete[] p; // 错误
```

#### 错误3：悬空指针访问（dangling pointer）
```cpp
int *p1 = new int(99);
int *p2 = p1;
delete p1;
*p2 = 999; // 错误：p2 已悬空
```

#### 错误4：误以为 delete 后会自动置空
```cpp
delete p;
if (p == nullptr) { ... } // 不可靠：delete 不会自动把 p 置空
```

建议：
- `delete` 后立刻写 `p = nullptr;`
- 一块内存只释放一次
- `new[]` 配 `delete[]`，`new` 配 `delete`

### 第102页：声明陷阱与链表连接陷阱

#### 陷阱1：指针声明只对紧邻变量生效
```cpp
Node* p1, p2, p3;
```
这里仅 `p1` 是指针，`p2`、`p3` 是普通 `Node` 对象。

若都要指针，写成：
```cpp
Node *p1, *p2, *p3;
```

#### 陷阱2：改了局部指针，不等于改了链表链接
```cpp
Node* next = head->next;
next = new Node; // 只改了 next 变量本身
```
上面不会把新结点接到链表里。

真正修改链表应写：
```cpp
head->next = new Node;
```

---

### 一页速记
- 未初始化指针不能解引用、不能释放。
- 字面量不能取地址。
- `delete` 后的指针可能悬空，需手动置 `nullptr`。
- 同一块内存不能二次释放。
- 指针声明要每个变量都带 `*`。
- 修改链表结构必须改“链接字段”（如 `head->next`），不是只改局部副本指针。

# 最终提交与海报说明

## 1. 当前项目完整度

这个项目已经可以作为数据库课程大作业提交，核心材料包括：

- `sql/01_schema.sql`：8 张核心表、主键、外键、检查约束和索引。
- `sql/02_views.sql`：当前可用设备、用户预约统计、未来预约详情 3 个视图。
- `sql/03_triggers.sql`：预约冲突、资质校验、维护冲突、设备状态同步、违约自动记录等触发器。
- `sql/04_seed_data.sql`：可演示的用户、实验室、设备、资质、预约、维护和违约样例。
- `scripts/build_db.sh`：一键重建数据库。
- `scripts/run_demo.sh`：一键展示系统查询结果。
- `scripts/run_validation.sh`：一键验证非法写入会被数据库拒绝。
- `frontend/`：可用于汇报展示的静态界面原型。
- `poster/final_poster.html`：期末提交海报，可直接用浏览器打开后打印为 PDF。

## 2. 交作业前建议检查

1. 重新构建数据库：

```bash
bash scripts/build_db.sh
```

2. 运行演示查询，确认 5 个模块都有输出：

```bash
bash scripts/run_demo.sh
```

3. 运行触发器验证，确认冲突预约、资质不足、维护冲突都会被拒绝：

```bash
bash scripts/run_validation.sh
```

4. 打开海报：

```bash
open poster/final_poster.html
```

5. 如果课程要求 PDF，把浏览器页面打印为 PDF。建议纸张选 A1 或 A2，方向选横向。

## 3. 海报讲解结构

海报按“为什么做、系统怎么组成、数据库怎么设计、功能怎么保证、展示结果”组织：

- 左侧说明问题背景：实验室设备预约容易出现时间冲突、资质不明、维护占用、违约难追踪。
- 中间展示系统组成：用户/管理员、预约管理、设备与实验室、维护工单、数据库规则层。
- 右侧展示数据库设计：8 张表、3 个视图、核心触发器、索引和约束。
- 底部展示功能亮点：可用设备查询、未来预约查询、用户预约统计、自动拒绝非法写入、no_show 自动记违约。

## 4. 答辩时可以强调的点

- 系统不是只在前端做判断，而是把关键业务规则写进数据库层。
- 即使绕过前端直接写 SQL，时间冲突、资质不足、维护冲突也会被触发器拒绝。
- 表之间用外键保持引用一致性，用检查约束限制枚举状态，用索引支持按设备和时间的高频查询。
- 视图把复杂查询封装成稳定接口，方便前端和管理员直接读取。

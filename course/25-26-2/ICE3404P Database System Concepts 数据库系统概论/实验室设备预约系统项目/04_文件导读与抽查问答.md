# 04. 文件导读与抽查问答

## A. 每个文件是干什么的

1. `sql/01_schema.sql`
- 建 8 张表 + 主外键 + 检查约束 + 索引
- 回答“你数据结构怎么设计”

2. `sql/02_views.sql`
- 建 3 个视图：可用设备、用户预约统计、未来预约
- 回答“你怎么给上层统一数据口径”

3. `sql/03_triggers.sql`
- 触发器实现核心规则：
  - 时间合法
  - 冲突校验
  - 资质校验
  - 维护冲突校验
  - no_show 自动记违约
- 回答“你怎么保证规则不被绕过”

4. `sql/04_seed_data.sql`
- 样例数据，包含成功数据和违约演示
- 回答“你怎么验证设计有效”

5. `scripts/build_db.sh`
- 一键建库，保证可重复初始化

6. `scripts/run_demo.sh`
- 一键查结果，用于汇报现场演示

7. `scripts/run_validation.sh`
- 一键跑非法写入，证明触发器会拦截

8. `scripts/udf_demo.py`（可选）
- 演示 SQLite 中如何通过宿主语言注册 SQL 函数

## B. 老师可能问的问题（建议回答）

### Q1: 你这里“函数”在哪？

A:
- SQLite 引擎不支持像 PostgreSQL/MySQL 那样的 `CREATE FUNCTION` 持久函数对象。
- 本项目把核心规则放在 `TRIGGER + VIEW + CHECK + FK` 实现。
- 同时提供了 `scripts/udf_demo.py`，演示如何注册 UDF 函数给 SQL 使用。

### Q2: 为什么不把规则写在应用层？

A:
- 应用层可以漏校验；数据库层不会漏。
- 多入口（脚本、接口、管理后台）共用数据库时，DB 层规则最可靠。

### Q3: 你怎么证明触发器生效？

A:
- 运行 `bash scripts/run_validation.sh`。
- 三条非法数据分别因“冲突/资质/维护冲突”被拒绝。

### Q4: 你的设计怎么体现规范化？

A:
- 主数据（用户、设备、实验室）与过程数据（预约、签到、维护、违约）分表。
- 减少冗余与更新异常，满足 3NF 设计思路。
